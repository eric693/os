歡迎來到第十四週的課程！系統效能監控與除錯是系統管理員和開發人員必備的技能。了解系統如何運作、發現效能瓶頸、診斷程式錯誤，這些能力對於維護穩定高效的系統至關重要。

一、系統效能指標

1.1 效能指標類型

主要效能指標

  • CPU 指標：
    • 使用率（User、System、Idle、I/O Wait）
    • 負載平均（Load Average）
    • Context Switch 次數
  • 記憶體指標：
    • 總量、已使用、可用
    • Swap 使用情況
    • 快取和緩衝
    • 分頁錯誤次數
  • 磁碟 I/O 指標：
    • 讀寫速度（MB/s、IOPS）
    • I/O Wait 時間
    • 佇列長度
  • 網路指標：
    • 頻寬使用率
    • 封包遺失率
    • 連線數
    • 延遲

1.2 負載平均（Load Average）

負載平均表示系統在一段時間內平均有多少行程在等待執行。

Load Average 解讀

通常顯示三個數字：1 分鐘、5 分鐘、15 分鐘的平均值

  • 單核心系統：1.0 表示 100% 使用率
  • 四核心系統：4.0 表示 100% 使用率
  • 負載 > 核心數：系統過載
  • 負載遞增：問題正在惡化
  • 負載遞減：問題正在改善

二、效能監控工具

2.1 top / htop

即時顯示系統資源使用情況和行程資訊。

欄位 說明
PID 行程 ID
USER 執行使用者
PR/NI 優先權/Nice 值
VIRT 虛擬記憶體大小
RES 實際使用的記憶體
SHR 共享記憶體
%CPU CPU 使用率
%MEM 記憶體使用率
TIME+ 累計 CPU 時間

2.2 vmstat

報告虛擬記憶體統計資訊。

vmstat 輸出範例： $ vmstat 1 5 procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu----- r b swpd free buff cache si so bi bo in cs us sy id wa st 2 0 0 512340 85640 892756 0 0 12 45 156 312 5 2 92 1 0 1 0 0 510120 85640 894580 0 0 0 128 168 325 6 2 91 1 0 欄位說明： r: 等待執行的行程數 b: 不可中斷睡眠的行程數 swpd: 已使用的 swap free: 可用記憶體 buff: 緩衝記憶體 cache: 快取記憶體 si: 從磁碟 swap in 的記憶體 so: 從記憶體 swap out 的量 bi: 從區塊裝置讀取的量 bo: 寫入區塊裝置的量 in: 每秒中斷次數 cs: 每秒 context switch 次數 us: 使用者時間百分比 sy: 系統時間百分比 id: 閒置時間百分比 wa: I/O 等待時間百分比

2.3 iostat

報告 CPU 和磁碟 I/O 統計資訊。

2.4 netstat / ss

顯示網路連線、路由表、網路介面統計。

2.5 sar

收集、報告和儲存系統活動資訊。

監控工具總覽

工具 主要用途 特點

三、除錯工具

3.1 GDB（GNU Debugger）

最強大的 C/C++ 程式除錯工具。

GDB 常用指令

  • 啟動除錯：gdb ./program
  • 設定中斷點：break main, break file.c:10
  • 執行程式：run [args]
  • 單步執行：step（進入函數）, next（跳過函數）
  • 繼續執行：continue
  • 查看變數：print variable
  • 查看堆疊：backtrace
  • 查看記憶體：x/10x address
  • 設定觀察點：watch variable

3.2 strace

追蹤系統呼叫和信號。

strace 用途
  • 查看程式呼叫了哪些系統呼叫
  • 診斷程式掛起或效能問題
  • 了解程式如何與系統互動
  • 追蹤檔案開啟、網路連線等

3.3 ltrace

追蹤函式庫呼叫。

3.4 Valgrind

記憶體除錯和效能剖析工具。

Valgrind 工具集

  • Memcheck：記憶體錯誤偵測
    • 記憶體洩漏
    • 使用未初始化的記憶體
    • 非法記憶體存取
    • 重複釋放記憶體
  • Cachegrind：快取效能分析
  • Callgrind：呼叫圖剖析
  • Helgrind：執行緒錯誤偵測
  • Massif：堆疊剖析

四、效能剖析

4.1 什麼是 Profiling？

效能剖析是分析程式執行時的行為，找出效能瓶頸的過程。

4.2 gprof

GNU 效能剖析工具。

使用 gprof 的步驟
  1. 編譯時加上 -pg 選項：gcc -pg program.c -o program
  2. 執行程式：./program
  3. 生成分析報告：gprof program gmon.out > analysis.txt

4.3 perf

Linux 效能分析工具，可以進行 CPU 剖析、追蹤事件等。

4.4 火焰圖（Flame Graph）

視覺化的效能剖析結果，可以快速找出熱點函數。

五、效能優化策略

5.1 優化原則

優化的黃金法則
  • 不要過早優化（Premature optimization is the root of all evil）
  • 先測量，再優化
  • 專注於瓶頸
  • 優化後要驗證
  • 注意可讀性與維護性

5.2 常見優化方向

CPU 優化

  • 減少不必要的計算
  • 使用更高效的演算法
  • 利用快取局部性
  • 並行化處理
  • 減少 context switch

記憶體優化

  • 減少記憶體配置次數
  • 使用記憶體池
  • 避免記憶體洩漏
  • 減少記憶體碎片
  • 使用適當的資料結構

I/O 優化

  • 使用緩衝
  • 批次處理
  • 非同步 I/O
  • 減少磁碟存取
  • 使用快取

六、實作練習

6.1 系統監控腳本

system_monitor.sh 系統資源監控腳本 
#!/bin/bash

# 系統監控腳本

LOG_FILE="system_monitor.log"
INTERVAL=5

echo "系統監控開始 - $(date)" | tee -a $LOG_FILE
echo "========================================" | tee -a $LOG_FILE

while true; do
    echo "" | tee -a $LOG_FILE
    echo "=== 時間: $(date) ===" | tee -a $LOG_FILE
    
    # CPU 資訊
    echo "--- CPU 使用率 ---" | tee -a $LOG_FILE
    top -bn1 | grep "Cpu(s)" | tee -a $LOG_FILE
    
    # 記憶體資訊
    echo "--- 記憶體使用 ---" | tee -a $LOG_FILE
    free -h | tee -a $LOG_FILE
    
    # 磁碟使用
    echo "--- 磁碟使用 ---" | tee -a $LOG_FILE
    df -h | grep -v tmpfs | tee -a $LOG_FILE
    
    # 負載平均
    echo "--- 負載平均 ---" | tee -a $LOG_FILE
    uptime | tee -a $LOG_FILE
    
    # Top 5 CPU 使用行程
    echo "--- Top 5 CPU 使用行程 ---" | tee -a $LOG_FILE
    ps aux --sort=-%cpu | head -6 | tee -a $LOG_FILE
    
    # Top 5 記憶體使用行程
    echo "--- Top 5 記憶體使用行程 ---" | tee -a $LOG_FILE
    ps aux --sort=-%mem | head -6 | tee -a $LOG_FILE
    
    # 網路連線統計
    echo "--- 網路連線統計 ---" | tee -a $LOG_FILE
    ss -s | tee -a $LOG_FILE
    
    sleep $INTERVAL
done

6.2 GDB 除錯練習

buggy_program.c 包含錯誤的程式（用於除錯練習） 
#include <stdio.h>
#include <stdlib.h>

int divide(int a, int b) {
    return a / b;  // 可能除以零
}

void array_access(int* arr, int size, int index) {
    printf("Value: %d\n", arr[index]);  // 可能越界
}

int* create_array() {
    int arr[5] = {1, 2, 3, 4, 5};
    return arr;  // 返回局部變數位址（錯誤！）
}

int main() {
    int result;
    int arr[5] = {1, 2, 3, 4, 5};
    
    // Bug 1: 除以零
    result = divide(10, 0);
    printf("Result: %d\n", result);
    
    // Bug 2: 陣列越界
    array_access(arr, 5, 10);
    
    // Bug 3: 使用已釋放的記憶體
    int* ptr = malloc(sizeof(int) * 5);
    free(ptr);
    ptr[0] = 10;  // 使用已釋放的記憶體
    
    // Bug 4: 記憶體洩漏
    int* leak = malloc(sizeof(int) * 100);
    // 忘記 free(leak);
    
    return 0;
}

6.5 效能剖析工具

performance_test.c 效能測試程式 
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define SIZE 1000000

// 效能較差的版本（頻繁的記憶體配置）
void slow_version() {
    for (int i = 0; i < SIZE; i++) {
        int* temp = malloc(sizeof(int));
        *temp = i;
        free(temp);
    }
}

// 效能較好的版本（一次配置）
void fast_version() {
    int* arr = malloc(sizeof(int) * SIZE);
    for (int i = 0; i < SIZE; i++) {
        arr[i] = i;
    }
    free(arr);
}

void measure_time(void (*func)(), const char* name) {
    clock_t start = clock();
    func();
    clock_t end = clock();
    
    double time_spent = (double)(end - start) / CLOCKS_PER_SEC;
    printf("%s: %.4f 秒\n", name, time_spent);
}

int main() {
    printf("效能比較測試\n");
    printf("================\n");
    
    measure_time(slow_version, "慢速版本");
    measure_time(fast_version, "快速版本");
    
    return 0;
}

7. 問答題：說明如何使用監控工具診斷系統效能問題

參考答案：診斷系統效能問題的步驟：(1) 使用 top/htop 查看整體資源使用情況，識別異常行程；(2) 使用 vmstat 檢查記憶體和 swap 使用，判斷是否有記憶體壓力；(3) 使用 iostat 分析磁碟 I/O，檢查是否有 I/O 瓶頸；(4) 使用 netstat/ss 檢查網路連線狀態；(5) 查看 Load Average 判斷系統負載趨勢；(6) 使用 sar 分析歷史資料找出規律。根據監控結果，針對性地優化：CPU 過高則優化演算法或增加並行；記憶體不足則優化記憶體使用或增加實體記憶體；I/O Wait 高則優化磁碟存取或使用 SSD。

8. 問答題：解釋記憶體洩漏的成因及如何使用工具偵測

參考答案：記憶體洩漏是指程式配置記憶體後未正確釋放，導致記憶體逐漸耗盡。常見原因：(1) malloc/new 後忘記 free/delete；(2) 迴圈中重複配置；(3) 異常處理路徑中未釋放；(4) 資料結構未完整清理。偵測方法：使用 Valgrind 的 Memcheck 工具，編譯時加上 -g 選項，執行 'valgrind --leak-check=full ./program'，報告會顯示洩漏的位置、大小和呼叫堆疊。也可使用 AddressSanitizer（編譯時加 -fsanitize=address）進行即時偵測。預防方法：使用 RAII 模式、智慧指標、記憶體池，養成配置後立即規劃釋放的習慣。
