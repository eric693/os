一、虛擬化基礎概念

1.1 什麼是虛擬化？

虛擬化是一種技術，可以在單一實體硬體上建立多個模擬的環境或專用資源。透過虛擬化，一台實體伺服器可以執行多個虛擬機器，每個虛擬機器都有自己的作業系統和應用程式。

虛擬化的優勢

  • 資源利用率提升：充分使用硬體資源
  • 成本降低：減少實體伺服器數量
  • 隔離性：各虛擬機器互不影響
  • 靈活性：快速建立和部署新環境
  • 易於管理：集中管理多個系統
  • 災難復原：快照和遷移功能

1.2 虛擬化的類型

伺服器虛擬化

在單一實體伺服器上執行多個虛擬伺服器。

桌面虛擬化（VDI）

在伺服器上執行桌面作業系統，使用者透過網路存取。

應用程式虛擬化

將應用程式與底層作業系統隔離。

儲存虛擬化

將多個實體儲存裝置整合為單一虛擬儲存池。

網路虛擬化

將網路資源虛擬化，如 VLAN、VPN。

二、Hypervisor 架構

2.1 什麼是 Hypervisor？

Hypervisor（虛擬機器監視器，VMM）是一個軟體層，負責建立和管理虛擬機器，並在實體硬體和虛擬機器之間進行資源分配。

安裝位置 直接在硬體上 在主機作業系統上
效能 高（直接存取硬體） 較低（需透過主機 OS）
複雜度 較複雜 較簡單
安全性 較高 較低
應用場景 資料中心、雲端平台 開發測試、個人使用

2.3 虛擬化技術

完全虛擬化（Full Virtualization）

特性

  • Guest OS 無需修改
  • 使用二進位轉譯技術
  • 硬體輔助虛擬化（VT-x, AMD-V）
  • 效能較好但有額外負擔
  • 範例：VMware, KVM

半虛擬化（Para-virtualization）

特性

  • Guest OS 需要修改
  • 透過 Hypercall 直接與 Hypervisor 通訊
  • 效能較完全虛擬化好
  • 但 Guest OS 需特別支援
  • 範例：Xen

2.4 硬體輔助虛擬化

現代 CPU 提供硬體層級的虛擬化支援：

  • Intel VT-x：Intel 虛擬化技術
  • AMD-V：AMD 虛擬化技術
  • EPT/NPT：記憶體虛擬化加速
  • VT-d/AMD-Vi：I/O 虛擬化

三、容器技術

3.1 什麼是容器？

容器是作業系統層級的虛擬化技術，多個容器共享同一個作業系統核心，但彼此隔離。

容器 vs 虛擬機器

  • 容器：
    • 共享主機核心
    • 啟動快速（秒級）
    • 資源占用少
    • 適合微服務
  • 虛擬機器：
    • 完整的 Guest OS
    • 啟動較慢（分鐘級）
    • 資源占用多
    • 隔離性更強

3.2 Docker 基礎

Docker 是最流行的容器平台，提供完整的容器生命週期管理。

Docker 核心概念

  • 映像檔（Image）：容器的模板，唯讀
  • 容器（Container）：映像檔的執行實例
  • Dockerfile：建立映像檔的腳本
  • Docker Hub：映像檔倉庫
  • Volume：持久化資料儲存
  • Network：容器間的網路通訊

3.3 Linux Namespace

Namespace 提供隔離的執行環境，讓容器看起來像是獨立的系統。

Namespace 隔離內容 說明
PID 行程 ID 容器內的行程看不到主機的行程
NET 網路 獨立的網路堆疊（IP、路由表）
MNT 掛載點 獨立的檔案系統視圖
UTS 主機名稱 獨立的主機名稱和域名
IPC 行程間通訊 隔離訊息佇列、信號量
USER 使用者 ID 使用者和群組 ID 的映射

3.4 Cgroups（Control Groups）

Cgroups 用於限制、記錄和隔離行程群組使用的資源。

Cgroups 可控制的資源

  • CPU：限制 CPU 使用率和核心分配
  • Memory：限制記憶體使用量
  • Disk I/O：限制磁碟讀寫速度
  • Network：限制網路頻寬
  • Device：控制裝置存取權限

四、虛擬化效能

4.1 虛擬化開銷

  • CPU 虛擬化：指令模擬和轉譯的開銷
  • 記憶體虛擬化：頁表轉換的額外層級
  • I/O 虛擬化：虛擬裝置的開銷
  • 網路虛擬化：虛擬交換器的處理

4.2 效能優化技術

優化方法
  • CPU Pinning：將虛擬 CPU 綁定到實體核心
  • NUMA 感知：考慮記憶體位置
  • 大頁面：減少 TLB miss
  • SR-IOV：硬體輔助的 I/O 虛擬化
  • 準虛擬化驅動：使用 virtio 等

5.4 Namespace 實驗

namespace_demo.c 建立 PID Namespace 
#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

#define STACK_SIZE (1024 * 1024)

static char child_stack[STACK_SIZE];

int child_function(void* arg) {
    printf("子行程 PID: %d\n", getpid());
    printf("父行程 PID: %d\n", getppid());
    
    // 執行 bash
    execl("/bin/bash", "bash", NULL);
    
    return 0;
}

int main() {
    printf("主行程 PID: %d\n", getpid());
    
    // 建立新的 PID namespace
    pid_t child_pid = clone(
        child_function,
        child_stack + STACK_SIZE,
        CLONE_NEWPID | SIGCHLD,
        NULL
    );
    
    if (child_pid == -1) {
        perror("clone failed");
        exit(EXIT_FAILURE);
    }
    
    printf("建立的子行程 PID: %d\n", child_pid);
    
    // 等待子行程
    waitpid(child_pid, NULL, 0);
    
    return 0;
}

5.5 Cgroups 資源限制

cgroup_limit.sh 使用 Cgroups 限制資源 
#!/bin/bash

# 限制 Docker 容器的 CPU 和記憶體

# 限制 CPU（50% 的一個核心）
docker run -d --name cpu-limited \
  --cpus="0.5" \
  ubuntu:latest \
  /bin/bash -c "while true; do echo test; done"

# 限制記憶體（512MB）
docker run -d --name memory-limited \
  --memory="512m" \
  --memory-swap="512m" \
  ubuntu:latest \
  sleep infinity

# 限制 CPU 和記憶體
docker run -d --name resource-limited \
  --cpus="1.0" \
  --memory="1g" \
  --memory-swap="1g" \
  ubuntu:latest \
  sleep infinity

# 查看資源使用
docker stats resource-limited

# 清理
docker stop cpu-limited memory-limited resource-limited
docker rm cpu-limited memory-limited resource-limited

7. 問答題：說明容器和虛擬機器的主要差異及各自的適用場景

參考答案：容器和虛擬機器的主要差異：(1) 架構：容器共享主機核心，虛擬機器有完整的 Guest OS；(2) 啟動速度：容器秒級，虛擬機器分鐘級；(3) 資源占用：容器 MB 級，虛擬機器 GB 級；(4) 隔離性：虛擬機器隔離性更強，容器為行程級隔離。適用場景：容器適合微服務架構、快速部署、CI/CD、開發測試環境；虛擬機器適合需要完全隔離的場景、執行不同作業系統、傳統應用遷移、需要完整系統控制的情況。

8. 問答題：解釋 Namespace 和 Cgroups 如何共同實現容器隔離

參考答案：Namespace 和 Cgroups 是 Linux 容器的兩大核心技術。Namespace 提供資源的隔離視圖：PID namespace 讓容器有獨立的行程空間；NET namespace 提供獨立的網路堆疊；MNT namespace 隔離檔案系統；UTS namespace 隔離主機名稱；IPC 和 USER namespace 分別隔離行程間通訊和使用者權限。Cgroups 則負責資源限制與計量：限制 CPU 使用率、記憶體上限、磁碟 I/O 頻寬、網路頻寬等。兩者結合：Namespace 確保容器看到的是獨立的系統資源，Cgroups 確保容器不會消耗過多資源影響其他容器，共同實現輕量級但有效的隔離。
